The hard filter: rules before similarity

The module without its own route: hardFilter protects the semantic scorer from obvious mismatches.

GlossaryPipeline← PreviousNext → /embed
Your win

Given a profile and an opening, predict whether it survives — and distinguish a hard exclusion from an exclude-term flag.

Where this module runs

hardFilter is called inside runScan, not directly by an HTTP route:

const { results } = await env.APP_DB.prepare('SELECT * FROM openings').all<OpeningRow>()
const survivors = hardFilter(results.map(fromRow), profile).survivors

It returns both survivors and flagged. The current scan uses only survivors; the flagged result is available for a future UI badge or review surface.

Five hard decisions

  • Remote: Remote only requires Remote; Hybrid ok rejects only Onsite; Onsite ok accepts everything.
  • Location: an empty preference accepts all; otherwise any preferred string must appear in the primary or secondary locations, case-insensitively.
  • Compensation: missing salary (salaryMax === 0) is not rejected. INR compares with compFloorInr; USD with compFloorUsd; unknown currencies pass.
  • Seniority: the title must contain a keyword for the selected level. For Senior+, keywords are senior, staff, lead, principal.
  • Employment: Contract requires Contract; Full-time requires FullTime.

Flag is not drop

const terms = profile.excludeTerms.filter((t) =>
  `${o.title} ${o.descriptionPlain}`.toLowerCase().includes(t.toLowerCase()),
)
if (terms.length > 0) flagged.push({ opening: o, terms })

Exclude terms are deliberately different. An opening containing “visa sponsorship” or another user-specified term is flagged, but it can still enter survivors if it passes the hard rules. This preserves recall while making a concern visible.

Design principle

Rules encode constraints that should not be negotiated by semantic similarity. A resume can be very similar to an onsite role, but similarity cannot make onsite acceptable to someone who chose remote-only.

A concrete trace

Profile: Remote only, locations [“India”], USD floor $120k, Senior+, Full-time. Opening: title “Senior Backend Engineer”, remote Remote, location “India”, salary max $150k, FullTime. It survives every hard rule. An opening titled “Backend Engineer” would fail the Senior keyword test; an Onsite senior role would fail remote; an unreported salary would pass compensation because unknown pay is not filtered out.
