POST /scan: request the whole pipeline

The HTTP route queues work; the consumer runs ingest → filter → embed → score → reason later.

Your win

Explain why /scan returns a jobId instead of waiting, and trace the scan status from queued to running to done or error.

The producer route

app.post('/scan', async (c) => {
  const body = await c.req.json<{ userId?: number }>()
  const userId = body.userId ?? 1
  const jobId = crypto.randomUUID()
  await markScan(c.env, jobId, 'queued')
  await c.env.SCAN_QUEUE.send({ jobId, userId })
  return c.json({ jobId })
})

The route does four small things: choose a user, create an ID, persist a queued status, and send a message. It returns immediately after the queue accepts the message. This prevents a client request from holding open while external feeds, embeddings, vector search, and LLM calls run.

The consumer

async queue(batch, env) {
  for (const msg of batch.messages) {
    const { jobId, userId } = msg.body
    await markScan(env, jobId, 'running')
    try {
      const report = await runScan(env, userId)
      await markScan(env, jobId, 'done', JSON.stringify(report))
    } catch (e) {
      await markScan(env, jobId, 'error', e instanceof Error ? e.message : String(e))
    }
  }
}

Cloudflare invokes this exported queue method for messages from the configured consumer. Each message is processed in order within this batch loop. The status table provides a durable progress record that another request can read.

runScan is the composition root

  1. loadProfile reads the resume and JSON filters for the user.
  2. ingestBoards refreshes every tracked board.
  3. All openings are loaded and passed through hardFilter.
  4. The resume and survivor descriptions are embedded in one batch.
  5. Vectors are stored in D1 and upserted into Vectorize.
  6. The resume vector queries Vectorize; scores become fit.
  7. The top ten openings receive generated reason text.

It returns { boards, survivors, ranked }, which is serialized into the scan's detail field on success.

Polling the result

app.get('/scan/:id', async (c) => {
  const row = await c.env.APP_DB.prepare(
    'SELECT * FROM scans WHERE id = ?',
  ).bind(c.req.param('id')).first()
  return c.json(row ?? { error: 'not found' })
})

The path parameter is bound into a single-row query. A caller can poll this endpoint with the returned job ID until status is terminal.
