/openings: showing scored jobs

Two read routes: all scored openings, or scored openings still actionable for one user.

Your win

Explain the difference between /openings and /openings/ranked, including why the second route joins against state.

GET /openings

const { results } = await c.env.APP_DB.prepare(
  'SELECT * FROM openings WHERE fit > 0 ORDER BY fit DESC',
).all<OpeningRow>()
return c.json(results.map(fromRow))

This route reads from APP_DB, keeps only openings whose fit has been computed, sorts the best match first, then calls fromRow on every row.

Why fromRow?

SQLite columns are snake_case: secondary_locations, salary_min, description_plain. The TypeScript domain object is camelCase: secondaryLocations, salaryMin, descriptionPlain. fromRow is the boundary adapter. It also parses the JSON string in secondary_locations and converts bonus from an integer to a boolean.

GET /openings/ranked

const userId = Number(c.req.query('user') ?? 1)
const { results } = await c.env.APP_DB.prepare(
  `SELECT o.* FROM openings o
   WHERE o.fit > 0
     AND o.id NOT IN (
       SELECT opening_id FROM state
       WHERE user_id = ? AND status IN ('applied','dismissed')
     )
   ORDER BY o.fit DESC`,
).bind(userId).all<OpeningRow>()

It uses the same score ordering, but applies a user-specific exclusion. A job the user already applied to or dismissed should not keep appearing in the actionable feed. A saved job remains visible.

Important distinction

fit > 0 means “the scoring pipeline has produced a positive score,” not “the job passed every preference.” The hard-filter step happens earlier in the full scan; this read route trusts the stored score.

Two boundaries, two shapes

Inside the Worker, Opening is a useful camelCase object. At the database boundary, OpeningRow mirrors SQL. Converting at one explicit boundary is safer than leaking database naming into every module.

Primary source

D1's Worker API, paired with the source itself in src/ingest/normalize.ts: database rows are storage shape; Opening is application shape.
