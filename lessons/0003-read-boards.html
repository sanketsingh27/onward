GET /boards: reading configuration

The first real route: a parameterized SQL query against the source database.

GlossaryRoutes← PreviousNext → /openings
Your win

Read the D1 chain prepare → all, identify which database is queried, and explain why this route returns board configuration rather than jobs.

The handler

app.get('/boards', async (c) => {
  const { results } = await c.env.BOARD_DB.prepare(
    'SELECT slug, company_name, feed_url, ats, last_fetched_at FROM boards ORDER BY slug',
  ).all()
  return c.json(results)
})

This is an asynchronous route because the database call crosses the Worker-to-D1 boundary. The handler waits for the query, then serializes the resulting array as JSON.

Read the D1 method chain

  1. c.env.BOARD_DB selects the D1 binding. This is the source/config database from lesson 1.
  2. prepare(sql) creates a prepared statement. Even without user input, this is the standard D1 query shape.
  3. all() executes the statement and returns an object with a results array.
  4. c.json(results) returns only the rows, not D1's wrapper object.

The SQL selects the fields needed to describe each feed: a stable slug, display name, feed URL, ATS type, and fetch timestamp. ORDER BY slug makes the response deterministic for callers and humans.

What this route does not do

It does not fetch a board, normalize jobs, or update last_fetched_at. It is a read-only inspection route. The work begins when POST /ingest calls ingestBoards.
