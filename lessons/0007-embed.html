POST /embed: meaning as numbers

Why the matching system converts a resume and job descriptions into vectors before comparing them.

Your win

Explain an embedding as a fixed-length numerical representation, and trace {texts} to {data} through the Workers AI binding.

The endpoint

app.post('/embed', async (c) => {
  const body = await c.req.json<{ texts?: string[] }>()
  if (!body.texts?.length) return c.json({ error: 'missing texts' }, 400)
  const data = await embedTexts(c.env.AI, body.texts)
  return c.json({ data })
})

The route is a small diagnostic/API surface: it accepts an array of texts, rejects a missing or empty array, calls the embedding helper, and returns the model's vectors. It does not store anything.

What is an embedding?

An embedding is a list of numbers representing the meaning and relationships learned from text. The model used here is @cf/baai/bge-base-en-v1.5. Cloudflare documents this model as producing 768-dimensional vectors. “Backend engineer with Python” and “server-side Python developer” should land near one another in vector space even when their words differ.

The important contract is not the individual number. It is that the same model maps a resume and an opening description into the same coordinate system. Similarity can then be calculated mechanically.

The helper

const EMBED_MODEL = '@cf/baai/bge-base-en-v1.5'

export async function embedTexts(ai: Ai, texts: string[]): Promise<number[][]> {
  const res = await ai.run(EMBED_MODEL, { text: texts })
  const output = res as { data: number[][] }
  return output.data
}

ai.run is a binding call, not an HTTP request you construct yourself. The array input is important: the scan embeds the resume and all survivor descriptions in one model call. The returned outer array lines up with the input order: vectors[0] belongs to texts[0], and so on.

Keep this distinction

Embedding is not ranking. It creates representations. Vectorize performs the comparison in the next stage; the LLM later writes an explanation.
