POST /ingest: from board feed to opening row

Fetch external JSON, normalize it into one internal shape, then replace each board's rows.

GlossaryPipeline← PreviousNext → hard filter
Your win

Trace one job from an Ashby feed to an APP_DB.openings row, and explain why one failing board does not erase the other boards' results.

The route is a thin wrapper

app.post('/ingest', async (c) => {
  const outcomes = await ingestBoards(c.env)
  return c.json(outcomes)
})

The HTTP route does not contain the ingestion algorithm. It passes the Worker environment into ingestBoards and returns one outcome per configured board.

Inside ingestBoards

  1. Read slug, company_name, and feed_url from BOARD_DB.boards.
  2. For every board, call fetchBoard(feed_url). That uses the standard fetch API and throws when Ashby returns a non-2xx status.
  3. Call normalizeBoard. It drops explicitly unlisted jobs and maps Ashby's shape into the internal Opening type.
  4. Delete old rows for that board: DELETE FROM openings WHERE board = ?.
  5. Batch an INSERT OR REPLACE for the normalized jobs.
  6. Return { board, ok, openings }, or { board, ok:false, openings:0, error } if that board failed.

Normalization details

normalizeJob creates a stable ID from the final path segment of jobUrl, prefixed with the board slug. It extracts salary/equity/bonus components, derives Remote/Hybrid/Onsite, defaults missing text to empty strings, and initializes fit: 0. A job with isListed === false becomes null and is removed by normalizeBoard.

Reliability decision

Promise.all runs boards concurrently, but the try/catch is inside each board's callback. One broken feed returns one failed outcome; it does not reject the whole ingestion.

Primary source

Ashby Public Job Posting API — the external jobs[] feed that fetchBoard reads.
